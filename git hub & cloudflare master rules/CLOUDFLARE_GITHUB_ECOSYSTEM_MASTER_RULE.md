## ⚡ 3. CLOUDFLARE MASTER RULES, CONFIGURATIONS & COMMANDS

### Rule 3.1: Strict Subdomain-to-Page Resolution Law
Every registered subdomain MUST load its own full, dedicated web application or static site.
- In Cloudflare Pages: Each project must have its custom subdomain added under **Project Settings > Custom Domains** (e.g. `agency.zenvq.com` added to `zenvq-agency`).
- In Cloudflare DNS: Every subdomain must point directly to its corresponding Pages container:
  - **Type:** `CNAME`
  - **Name:** Single-slug identifier (`agency`, `tools`, `puson`, `templates`, `suggests`, `natures-intimacy`, `rafij`, `drjerin`, `boutique-templates`, `ruqyah`)
  - **Target:** `[slug].pages.dev` (or root `zenvq.com` for middleware-handled dynamic routes)
  - **Proxy Status:** ALWAYS **Proxied (Orange Cloud ☁️)** for edge SSL, HTTP/3, Brotli compression and DDoS mitigation
  - **TTL:** Auto

### Rule 3.2: Single Domain & Clean Slug Policy
- Duplicate domains pointing to the same utility (e.g. `mediadrop.zenvq.com` alongside `tools.zenvq.com`) are permanently prohibited. Maintain exactly one canonical subdomain per service.
- Never use random hashes or ephemeral tunnel URLs for production targeting.

### Rule 3.3: Cloudflare CLI Commands Reference (`wrangler`)
Agents and developers must use the standardized wrangler commands:

```bash
# 1. Authenticate with Cloudflare
npx wrangler login
npx wrangler whoami

# 2. Deploy Static Pages Project (Direct CLI Deploy)
# Syntax: npx wrangler pages deploy <output_dir> --project-name <project_name>
npx wrangler pages deploy ./out --project-name zenvq-agency
npx wrangler pages deploy ./out --project-name zenvq
npx wrangler pages deploy ./out --project-name zenvq-tools
npx wrangler pages deploy ./out --project-name puson-dev
npx wrangler pages deploy ./out --project-name natures-intimacy

# 3. Cloudflare Pages Project Management
npx wrangler pages project list
npx wrangler pages project create <project-name> --production-branch main
npx wrangler pages deployment list --project-name <project-name>

# 4. Cloudflare Worker Deployments (Scheduled Sentinels & Edge Functions)
cd "cloudflare-worker"
npx wrangler deploy
npx wrangler tail zenvq-all-site-guardian

# 5. Worker Secret Management (Encrypted at Edge)
npx wrangler secret put RECIPIENT_EMAIL
npx wrangler secret put TELEGRAM_BOT_TOKEN
```

   - Filter: `Cookie contains "zq_v2"`
   - Action: **Bypass cache**
2. **Preview & Admin Rate Limiting:**

## 🐙 4. GITHUB MASTER RULES, CONVENTIONS & REPOSITORIES

### Rule 4.1: Clean Git Credentials & Wincred Integration
- **Absolute Prohibition of Plaintext Tokens:** NEVER store personal access tokens (`ghp_...`) in git remote URLs, scripts, commit messages, or markdown documents.
- **Enforce Windows Credential Helper:** All repositories must use `wincred`:
  ```bash
  git config --global credential.helper wincred
  ```
- **Remotes Format:** Must always be clean HTTPS URLs without credentials:
  ```bash
  git remote set-url origin https://github.com/PusonDev/<Repository-Name>.git
  ```

### Rule 4.2: Standardized Commit Messages & CI Discipline
To avoid unnecessary CI rebuilds and maintain clean git histories:
- Auto-maintenance commits:
  ```bash
  git commit -m "chore(auto-maintenance): stage and synchronize verified files [skip ci]"
  ```
- Standard feature commits:
  ```bash
  git commit -m "feat(tree-sync): update ecosystem routing and page configurations"
  ```
- Bug fix commits:
  ```bash
  git commit -m "fix(edge-routing): resolve subdomain redirect loop"
  ```

### Rule 4.3: Lead Data & Confidentiality Boundary
- Collected client leads, inquiries, phone numbers and customer emails must NEVER be committed to Git.
- Lead storage is strictly isolated to Google Sheets (Protected ID: `1DTZIHaezjqg69wmaJh9UFhORhZU-hfsI4CrIIDZnxCk`) and encrypted local logs.
