## 🚀 3. CLOUDFLARE MASTER REGULATIONS & COMMANDS

### Ensuring Subdomains Properly Serve Pages:
To guarantee every subdomain loads its own distinct website and does not show an error or blank screen:
1. **Cloudflare Pages Custom Domains:**
   - In Cloudflare Dashboard, open **Workers & Pages > [Project Name] > Custom domains**.
   - Click **Set up a custom domain**.
   - Input the subdomain (e.g. `agency.zenvq.com`, `templates.zenvq.com`, `drjerin.zenvq.com`).
   - Confirm DNS record creation. Cloudflare will automatically provision edge SSL certificates.
2. **Cloudflare DNS Records:**
   - Record Type: `CNAME`
   - Name: `[slug]` (e.g. `agency`, `tools`, `puson`, `drjerin`)
   - Target: `[slug].pages.dev`
   - Proxy: **Proxied (Orange Cloud ☁️)**
3. **Single Domain Policy (L3-002):**
   - No duplicate aliases. Maintain only one canonical subdomain per project.

## 🐙 4. GITHUB MASTER REGULATIONS & COMMANDS

### Security & Credential Hygiene:
1. **Zero Leaked Personal Access Tokens:**
   - Never embed PAT tokens (`ghp_...`) into git remote strings.
   - Check remotes with:
     ```bash
     git remote -v
     ```
   - If a token is detected in the URL, sanitize it immediately to standard HTTPS:
     ```bash
     git remote set-url origin https://github.com/PusonDev/<Repo-Name>.git
     ```
   - Let Windows Credential Manager securely handle authentication:
     ```bash
     git config --global credential.helper wincred
     ```
2. **Automated Commit Discipline:**
   - Standard automated maintenance commits:
     ```bash
     git add -A
     git commit -m "chore(auto-maintenance): stage and synchronize verified files [skip ci]"
     git push origin main
     ```
3. **Lead Data Boundary:**
   - Lead prospect records are strictly forbidden from Git tracking. All inquiry records remain in Google Sheets and local encrypted CSV ledgers.
